Edit files THERE; never edit the symlinked destinations.

## Loading chains

Claude Code:
  ~/.claude/CLAUDE.md  ->  @agents-common.md + @claude-specific.md

OpenCode v2:
  ~/.config/opencode/AGENTS.md (shim, one-line pointer)
  ~/.config/opencode/opencode.json "instructions" array:
      agents-common.md + opencode-specific.md  (eager, deterministic)

## Contamination guarantees
- Claude Code never sees any path to opencode-specific.md.
- OpenCode never sees any path to claude-specific.md.
- agents-common.md contains zero file references, so nothing leaks from it.
- Claude Code falls back to AGENTS.md only when CLAUDE.md is absent; CLAUDE.md
  exists, so the fallback never fires.

## Reasoning notes
1. Single source of truth: 5 authored files, 2 symlinks, 1 config ref. Rule
   edits happen once, in ~/.agent/AGENT_INSTRUCTIONS/, and reach both CLIs.
2. Shims over plain symlinking of one big file: each CLI must load DIFFERENT
   runtime-specific rules. Claude Code reads CLAUDE.md, OpenCode reads
   AGENTS.md; the shim pattern lets both share one body without cross-loading.
3. Config "instructions" array for OpenCode specifics instead of @references:
   OpenCode has no native eager @import (that is Claude Code only; in OpenCode
   @refs are a lazy, model-dependent convention). The instructions array
   loads deterministically every session.
4. No @refs inside agents-common.md: Claude Code follows @imports eagerly and
   recursively. Any ref placed there would load for BOTH runtimes, breaking
   isolation.
5. Canonical tool terms (SHELL/QUESTION/SUBAGENT) in the shared body with a
   mapping table instead of IF-conditionals: one lookup beats many scattered
   runtime branches; models follow mapping tables more reliably.
6. Runtime-divergent behavior (subagent model syntax, hooks vs plugins,
   memory, skills frontmatter) moved into the two specific files rather than
   conditionalized inline.
7. ~/.claude/CLAUDE.md was ALREADY a symlink (to ~/.agent/CLAUDE.md); it was
   repointed, not overwritten. Original content backed up anyway.
